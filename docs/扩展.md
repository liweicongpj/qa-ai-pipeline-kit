# 扩展：适配不同项目和功能模块

## 不改框架就能调的（都在工作区里）

| 想改什么 | 怎么改 |
|---|---|
| 某一步交给 AI 的任务说明 | 把框架 `prompts/` 里的同名文件复制到工作区 `prompts/`，改工作区里那份；直接调接口用的在 `prompts/api/` |
| 测试点、需求、缺陷、审核表的格式 | 改工作区 `templates/` 里对应文件（审核表的表头别改，框架要读） |
| 风险分类 | `qa.config.json` 的 `risk_categories` |
| 功能模块 | 来自知识库 `wiki/modules/` 的页名；需求用 `--module` 标，缺陷自动带上，指标按模块汇总 |
| 模块之间的耦合 | `wiki/耦合关系.md` 那张表 |
| 被测服务 | `qa.py target set <名字> --url ... --start ... --health ...`，可以配多个 |
| 不变量 | `autotest/invariants.py` 的 `check(base_url)` |
| 各步骤用哪个模型 | `qa.config.json` 的 `stage_models` |
| 项目专用的模型（比如内网部署） | `qa.config.json` 的 `models` |
| 知识库放进提示词的上限 | `qa.config.json` 的 `context_chars`（默认 15 万字，超了按相关度挑页） |
| 关键步骤后自动做点什么 | `qa.config.json` 的 `hooks`（见下） |

## 钩子

```json
"hooks": {
  "after_review_ready": "python D:/tools/notify.py 有审核表要审",
  "after_accept": "python D:/tools/notify.py 需求定稿了",
  "after_autotest": "python D:/tools/notify.py 自动化跑完了",
  "after_gen": "",
  "after_wiki_commit": ""
}
```

| 钩子 | 什么时候 | 能读到的环境变量 |
|---|---|---|
| `after_review_ready` | 审核表生成后（`review`、`gen testpoints --review`、需求变更出了变更审核表） | `QA_REQ`、`QA_REVIEW`（审核表路径） |
| `after_accept` | 定稿后 | `QA_REQ` |
| `after_gen` | 每次直接调模型做完一步 | `QA_STEP`、`QA_OK`（1 = 检查通过）、`QA_REQ`、`QA_FILES`（写了哪些文件，JSON） |
| `after_autotest` | 接口自动化跑完 | `QA_RUN_DIR`、`QA_FAILED`、`QA_TOTAL` |
| `after_wiki_commit` | 知识库提交后 | `QA_MESSAGE` |

命令在工作区里运行，都能读到 `QA_EVENT`、`QA_WS`。可以用来发群通知（企业微信、钉钉、飞书机器人）、同步到缺陷系统、触发下一步流水线。整条线怎么接见 [自动流转](自动流转.md)。

## 改框架

- **加一种模型接口**：在 `qa_models.py` 写一个函数 `_xxx(m, system, user, cwd) -> Result`，加进 `call()` 里的对照表；要支持边查边写，再接收 `tools`、`run_tool`、`max_turns`，并加进 `TOOL_PROVIDERS`
- **加一步流程**：见 [开发说明](开发说明.md) 的“加一个新命令”（要同时写给 AI 工具和直接调模型的两份任务说明）
- **加一个命令**：照 `cmd_xxx(args)` 的样子写，在 `main()` 里注册
- 改完跑 `python qa.py selftest`，自检过了再提交

## 不同类型的项目

| 项目 | 资料 | 被测服务 |
|---|---|---|
| 网游 / 小游戏服务端 | 策划案、数值配置、协议文档、缺陷记录 | 本地服务端或测试服；云函数可以用一层很薄的 HTTP 桥接 |
| Web / App 后端 | 产品文档、接口文档（OpenAPI）、数据库表结构 | 本地或测试环境的 HTTP 服务 |
| 单机游戏 / 客户端逻辑 | 策划案、配置表 | 把核心逻辑包成本地 HTTP 或直接写 pytest 调函数（`tests` 目录里不一定非走 HTTP） |

接口自动化以外的测试（界面、性能、兼容）可以接别的工具，结果用 `defect new` 登记，同样回流进知识库。
