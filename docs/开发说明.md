# 开发说明

给维护框架的人（或 AI）看：代码怎么组织、加一个新命令要改哪里、改完怎么验证。

## 代码结构

`qa.py` 只是入口；代码按功能分在 `qakit/` 里，另外两个独立模块在仓库根目录：

| 文件 | 放什么 |
|---|---|
| `qa.py` | 入口：`python qa.py <命令>`；`import qa` 也能用（会把 qakit 里的名字都带出来） |
| `qakit/common.py` | 常量（框架位置 KIT、环境权限 ACCESS……）、读写文件、模板渲染、Markdown 表格和字段解析、时间、子进程 |
| `qakit/workspace.py` | 工作区（`Ws`：配置、进度、各目录）、找工作区、钩子、git 提交和推送 |
| `qakit/start.py` | doctor、setup、init、use、target |
| `qakit/ingest.py` | ingest：导入资料、记来源、打码、资料变化检测 |
| `qakit/corpus.py` | corpus、index、search、cfg、history、embed；生成测试点时取检索内容 |
| `qakit/wiki.py` | 耦合关系表、两两组合、模块清单、过时资料、待确认、wiki check / commit |
| `qakit/reqs.py` | req、review、accept、defect；测试点和审核表解析、需求变更、配置晚到 |
| `qakit/prompts.py` | prompt：每一步任务说明要填的变量（`prompt_values`，打印任务说明和直接调模型共用） |
| `qakit/gen.py` | bench、usage、models；出测试点、归因的提示词；记模型调用 |
| `qakit/steps.py` | gen：每一步直接调模型（拼资料、只读查资料工具、文件块输出、检查不过让模型改、重试和换模型） |
| `qakit/access.py` | access、exec、impact、抓包整理 |
| `qakit/autotest.py` | autotest：被测服务启停、跑 pytest |
| `qakit/metrics.py` | metrics、modules |
| `qakit/regress.py` | regress：版本回归 |
| `qakit/status.py` | status、next：上手进度和每日待办 |
| `qakit/selftest.py` | check、selftest |
| `qakit/cli.py` | 命令行参数和分发 |
| `qa_index.py` | 资料索引：读各种文件、切段、检索、配置表拆表、缺陷列识别（不依赖 qakit） |
| `qa_models.py` | 模型接入（不依赖 qakit） |

模块从上到下是“底层 → 上层”：上层可以直接 `from .底层 import ...`；少数底层要用上层的地方（会形成循环引用），写在函数里面导入，并带注释“上层模块，在函数里导入免得循环”。

## 加一个新命令

1. 在对应功能的模块里写 `cmd_xxx(args) -> int`：返回 0 表示成功；给用户看的话用 `out()` 打印，全用中文
2. 在 `qakit/cli.py` 里加参数（`sp.add_parser(...)`）和分发（`handler` 那张表）
3. 要交给 AI 做的步骤：两份任务说明都要写——`prompts/<名字>.md` 给在工作区里干活的 AI 工具（可以让它运行命令），`prompts/api/<名字>.md` 给框架直接调模型（资料由框架放进 `{{context}}`，模型只能调只读工具）。在 `qakit/prompts.py` 的 `PROMPTS` 里登记、在 `prompt_values` 里填变量；在 `qakit/steps.py` 的 `STEPS` 里写清能写哪些文件，在 `build_context` 里拼资料、`check_step` 里写检查、`after_step` 里写做完以后的提示
4. 要在 `status` 里提醒的：在 `qakit/status.py` 的 `daily()` 里加
5. 在 `qakit/selftest.py` 里加一项自检（端到端走一遍）；有新的解析规则，在 `tests/` 里加细粒度测试
6. 更新文档：`AGENTS.md` 的命令速查、`docs/日常.md`、新功能对应的文档；工作区规则模板 `templates/workspace_AGENTS.md`

## 约定

- 只用 Python 标准库（读 Word / Excel / PDF 的库是可选的，没装就跳过并提示）
- 给人看的数据都放 Markdown（进 git，人能直接改）；框架自己的进度放 `.qa/state.json`
- 人工关口不能省：知识库提交、测试点审核、用例清单、归因确认、缺陷是否漏测，都要停下来等人
- 判断对错用确定的计算和脚本，不让模型说“对”或“不对”
- 每一步都要能直接调模型（`gen <步骤>`）：网页、钩子、Jenkins 触发时旁边没有 AI 工具；直接调模型时模型只能读、不能自己写文件，写什么由框架按文件块收、检查后再落盘

## 验证

```
python -m pytest tests            细粒度测试（几秒）
python qa.py selftest             自检：临时文件夹里把整条流程走一遍（约 1 分钟，用假模型，不花钱）
python qa.py check                扫描密钥
```

推到 GitHub 后，`.github/workflows/selftest.yml` 会在 Windows / macOS / Linux、Python 3.10 和 3.12 上各跑一遍。自检失败时会把失败项和出错位置写成运行页面上的注释（Annotations），不登录也能看到。
