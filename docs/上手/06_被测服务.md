# 第 6 步：接上被测服务和接口文档

**谁做**：AI 问清楚后配置；动项目代码前先问用户。

## 先问用户

1. 被测服务能在本机跑起来吗？平时怎么启动、地址是什么？有没有健康检查地址（比如 /health）？
2. 有没有测试环境、能重置数据或调时钟的接口？（测跨天、次数上限时很有用）
3. 接口文档在哪？没有的话，AI 可以读服务端代码整理一份，给用户过目

## 怎么做

```
{{qa}} target set default --url http://127.0.0.1:8000 --start "npm run dev" --cwd D:\项目\server --health /health
{{qa}} ingest D:\项目\docs\接口文档.md --api
{{qa}} target list
```

- `--start` 可以不配：那就由用户自己启动服务，跑用例时不加 `--start`
- 一个项目有多个服务（比如游戏服、支付服、运营后台）：每个用 `target set <名字>` 配一份，用例和接口文档分开放，跑的时候 `autotest run --target <名字>`
- 服务没有 HTTP 接口（比如只是函数）：需要一个很薄的“桥接”服务把函数包成 HTTP，问用户同不同意在项目里加，加在开发工具目录、不进正式包

**做完的标准**：被测服务地址配好，至少有一份接口文档。
