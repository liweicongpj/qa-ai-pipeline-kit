# 环境与权限：三种环境怎么用

建工作区时用 `--access` 选环境，之后可以用 `{{qa}} access <环境>` 改。上手步骤和交给 AI 的任务说明会跟着变。

| 环境 | 能拿到什么 | 知识库 | 测试点 | 执行 | 自动化 |
|---|---|---|---|---|---|
| `blackbox` 无代码权限 | 策划案、文档、客户端、（能的话）抓包 | 用文档和历史缺陷建 | 照常 | `exec` 生成执行清单，人工执行、记结果 | 能抓包的：`ingest --har` 把请求整理成接口文档，再走接口自动化 |
| `interface` 开放接口或协议（默认） | 开放给测试的接口 / 协议和文档 | 文档 + 接口文档 | 照常 | 接口自动化为主，手工补充 | `tests-plan` → `tests-write` → `autotest run` |
| `source` 完整代码权限 | 服务端代码 | 文档 + 对照代码核对规则、从代码找出改同一数值的地方补耦合表 | 照常 | 同上 | 同上，另有 `impact`：按代码改动推荐回归范围 |

## 完整代码权限：登记代码位置

```
{{qa}} access source --source D:\项目\server D:\项目\shared
```

登记后：

- 整理知识库时，AI 可以读这些代码核对规则，找出改同一个数值的代码位置补进耦合关系表（资料和代码不一致时两边都写上，标“待确认”）
- 改版时：`{{qa}} impact --range v1.2..v1.3`（git 的改动范围），框架取出改动清单，AI 对照模块和耦合关系推荐要重跑的测试点和用例

## 自己公司的服务器

被测服务就是一个地址，不管它跑在本机、测试服还是云上：

```
{{qa}} target set game-test --url http://10.0.0.5:8080 --health health
{{qa}} target set gate-test --url tcp://10.0.0.5:9001
{{qa}} target set game-staging --url https://staging.example.com
```

- 服务一直在测试服上跑：不用配 `--start`，跑用例时也不加 `--start`
- 一个项目有多个服务（网关、游戏服、支付、运营后台）、多套环境（测试、预发），每个配一个名字，用例和接口文档分开放
- 不是 HTTP 的协议（TCP + protobuf、WebSocket）：地址写成 `tcp://`、`ws://`，健康检查只看端口通不通；用例照样是 pytest，由 AI 按协议文档（比如 .proto 文件）写一个协议客户端放在 autotest/ 下，用例调用它
- 测试环境要有能造数据的办法（GM 指令、测试账号、重置接口），写进接口文档，AI 写用例时会用

**做完的标准**：`access` 显示的环境对，完整代码权限时登记了代码位置。
