# 按最终测试点执行一轮并记录结果

**适用**：无代码权限的环境（也适合任何环境里接口测不到的部分：界面、手感、真机）。

1. 需求定稿后生成执行清单：

   ```
   {{qa}} exec R001 --round v1.0
   ```

2. 人按清单逐条执行，填“结果”：通过 / 失败 / 阻塞 / 未测；顶部填执行人、版本或环境、执行耗时
3. 失败的先登记缺陷：`{{qa}} defect new "标题" --req R001`，把缺陷编号（D001）填进执行记录
4. 填完检查：再运行一次 `{{qa}} exec R001 --round v1.0`，会显示通过、失败、阻塞、未测各多少
5. 漏测的缺陷（“被最终测试点覆盖”填否）照常回流：`{{qa}} prompt feedback`

能抓包的话，可以把抓到的请求导出成 HAR 文件（浏览器开发者工具、Charles、Fiddler 都能导），`{{qa}} ingest --har 文件.har` 自动整理成接口文档，之后就能走接口自动化。

**做完的标准**：有一份填完的执行记录。
