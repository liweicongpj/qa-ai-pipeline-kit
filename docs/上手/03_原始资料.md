# 第 3 步：放进原始资料

**谁做**：用户决定放哪些资料，AI 跑导入命令。资料里的事实以用户为准。

## 放什么

能让测试的人搞懂规则的都可以：策划案、数值配置、接口文档、以前的测试用例、缺陷记录、事故复盘、玩家反馈汇总。先放最核心的几个模块就行，以后随时加。

## 怎么做

1. 问用户：项目的资料在哪？哪些模块最重要？
2. 导入（文件或整个文件夹都行，只收文本类文件，单个不超过 2 MB）：

   ```
   {{qa}} ingest D:\项目\docs\策划案 D:\项目\config\economy.json
   ```

3. 没有现成文档的知识（只在用户脑子里的规则、踩过的坑），请用户口述，AI 整理成 Markdown 放进 raw/，给用户过目后保存
4. 以后项目资料改了，运行 `{{qa}} ingest --refresh` 一键按原路径刷新，`status` 会提示哪些知识页要更新

## 资料多的项目（几百份策划案、几千张配置表、成千上万条缺陷）

不要复制进 raw/，改成登记资料目录、建索引，资料留在原处：

```
{{qa}} corpus add D:\项目\策划案 --kind doc
{{qa}} corpus add D:\项目\配置表 --kind config
{{qa}} corpus add D:\项目\缺陷导出 --kind defect
{{qa}} index
```

raw/ 只放少量精选的文本资料（比如用户口述整理的规则）。详见 [大批资料与检索](../大批资料与检索.md)。

## 注意

- 不要放密钥、云环境 ID、AppID、玩家个人信息；导入后可以跑 `{{qa}} check` 扫一遍
- 前公司或第三方的内部资料，确认有权使用再放

**做完的标准**：raw/ 里至少有一份资料。
