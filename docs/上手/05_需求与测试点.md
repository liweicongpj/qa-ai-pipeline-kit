# 第 5 步：跑通第一个需求（生成 → 审核 → 定稿）

**谁做**：AI 生成，用户审核。

1. 建需求，标上属于哪些模块（模块名对应 wiki/modules/ 的页名，用来查耦合关系）：

   ```
   {{qa}} req new "广告宝箱" --from D:\项目\需求\广告宝箱.md --module 广告领奖
   ```

2. 生成测试点，两种方式选一种：
   - **工作区里的 AI 直接做**（不用 API 密钥）：`{{qa}} prompt testpoints R001`，照任务说明做
   - **直接调模型接口**（要先配模型清单，见 [多模型与选型](../多模型与选型.md)）：`{{qa}} gen testpoints R001 --model sonnet`，会自动记下 token、耗时、费用
3. 生成审核表：`{{qa}} review R001`。如果有耦合提醒（和别的模块共用的数值没测到），会在这里提示
4. 用户逐条填审核表：结论（采纳 / 改后采纳 / 否决）、否决原因、修改后的内容、补充的测试点、审核耗时。AI 可以一条条念、照用户说的记，**不能替用户判断**
5. 定稿：`{{qa}} accept R001`，生成 最终测试点.md，并记下采纳率、编造数、补充数

**想比较哪个模型出测试点更好**：用 `{{qa}} bench testpoints R001 --models a,b,c`，几个模型各出一份，顺序打乱，盲审后 `bench report` 揭晓，`bench adopt` 采用最好的那份。

**做完的标准**：有一个需求定稿。
