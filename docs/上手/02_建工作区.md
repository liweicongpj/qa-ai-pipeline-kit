# 第 2 步：建工作区

**谁做**：AI 问用户两件事，然后跑命令。

## 先问用户

1. **先用示例跑一遍，还是直接接自己的项目？** 第一次用强烈建议先跑示例（约 30 分钟）：示例自带资料、接口文档、一个需求和一个能本地启动的被测服务，每一步都能看到真实样子
2. **工作区放哪？** 一个空文件夹，不要放在框架文件夹里面。推荐 `D:\qa-workspace\<项目名>`（macOS / Linux：`~/qa-workspace/<项目名>`）。也可以放进项目自己的仓库（比如 `项目/qa-ai/`），这时框架提交时只提交这个文件夹里的改动

## 怎么做

```
python qa.py init D:\qa-workspace\示例 --example
python qa.py init D:\qa-workspace\我的项目 --name 我的项目
```

工作区的结构：

```
<工作区>/
├── AGENTS.md（= CLAUDE.md = GEMINI.md）  在工作区里干活的 AI 读的规则
├── qa.config.json   项目配置：被测服务、各步骤默认模型、风险分类、钩子
├── raw/             原始资料（只读，ingest 会记来源）
├── wiki/            AI 整理的知识库（模块页、耦合关系表、风险清单）
├── reqs/            每个需求一个文件夹：需求、测试点、审核表、最终测试点、模型对比
├── defects/         缺陷记录
├── autotest/        接口文档、用例、不变量、每次运行的结果
├── templates/ prompts/   本项目覆盖用的模板和任务说明
└── metrics/         指标
```

## 建好以后

请用户在工作区文件夹里开一个新的 AI 会话（Claude Code、Codex、Gemini CLI、Cursor 都行），它会读工作区的 AGENTS.md，接着 `status` 往下走。

**做完的标准**：`status` 能显示工作区。
