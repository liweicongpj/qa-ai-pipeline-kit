# 第 4 步：生成知识库并人工审核

**谁做**：AI 生成，用户审核。

1. AI 运行 `{{qa}} prompt wiki-build`，照打印出来的任务说明做：生成模块页、**耦合关系表**、风险清单、目录和变更记录
2. AI 运行 `{{qa}} wiki check`（格式：每页有来源、引用的资料都在、目录齐全、多模块时有耦合关系表）和 `{{qa}} coupling`（看耦合表读得对不对），有问题就修
3. 停下来请用户审核。重点看三样：
   - 模块页的规则对不对（每条都标了出自哪份资料，可以对着查）
   - 耦合关系表有没有漏：哪些数值会被好几个模块同时改（价格、金币、次数、库存、体力……），约束写对没有
   - “待确认”的地方，用户能答的当场答掉
4. 用户说可以后：`{{qa}} wiki commit -m "初版知识库"`

**为什么要耦合关系表**：AI 按需求出测试点时，容易只测需求里写到的那个模块。比如“购买”测得很全，却没想到“打折券”也会改价格，叠加后价格变负。有了这张表，框架会把相关模块一起交给 AI，生成后还会检查有没有漏（见 [架构说明](../架构.md) 的“耦合”一节）。

**做完的标准**：提交过一次知识库。
