# 目录说明

两个地方：**框架仓库**（就是这个仓库，公开，谁都能下载）和**工作区**（每个项目一个，放项目的私有资料和产出，`python qa.py init` 生成，不放进框架仓库）。

## 框架仓库

| 路径 | 放什么 |
|---|---|
| `README.md` | 这是什么、怎么开始 |
| `AGENTS.md` | 给 AI 的搭建和使用手册（CLAUDE.md、GEMINI.md 指向它，各家 AI 工具各读各的） |
| `qa.py` | 命令行工具：所有命令都在这里（只用 Python 标准库） |
| `qa_index.py` | 资料索引：读 Word / Excel / 网页 / PDF / JSON，切段、关键词和向量检索、配置表拆表、缺陷列识别 |
| `qa_models.py` | 模型接入：Claude、OpenAI 兼容接口、Gemini、命令行 AI 工具、假模型；记 token、耗时、费用 |
| `prompts/` | 每一步交给 AI 的任务说明（`qa.py prompt <名字>` 打印出来）；`prompts/api/` 是直接调模型时用的版本 |
| `templates/` | 新建工作区时复制过去的模板：工作区规则、测试点、需求、缺陷、审核表、conftest.py |
| `docs/上手/` | 上手 9 步，`qa.py next` 按进度打开对应那篇 |
| `docs/日常.md` | 上手后的日常用法：按两种开发流程写每个阶段跑什么，老项目接入、回归 |
| `docs/架构.md` | 怎么运作、自动化到什么程度、解决什么问题、耦合怎么查 |
| `docs/大批资料与检索.md` | 资料多时怎么建索引、检索、查配置表和缺陷；过时资料、模块名统一 |
| `docs/多模型与选型.md` | 接哪些模型、怎么对比、怎么选 |
| `docs/扩展.md` | 适配不同项目：覆盖提示词、钩子、加被测服务 |
| `docs/目录说明.md` | 这一页 |
| `examples/mini-shop/` | 示例项目：资料、接口文档、需求、能本地跑的被测服务、样例用例和不变量（`init --example` 用它） |
| `models.example.json` | 模型清单样例，复制成 `models.local.json` 再改（不进 git） |
| `requirements.txt` | 依赖（`qa.py setup` 安装） |
| `.github/workflows/` | GitHub 上自动跑自检（Windows / macOS / Linux） |

## 工作区

| 路径 | 放什么 | 谁写 |
|---|---|---|
| `AGENTS.md`（`CLAUDE.md`、`GEMINI.md` 内容相同） | 在这个工作区干活的 AI 要守的规则：环境、人工关口、各类资料怎么查 | 框架生成（`qa.py access` 会重新生成） |
| `README.md` | 给人看的：这个文件夹是什么、每个目录放什么、平时怎么用 | 框架生成 |
| `qa.config.json` | 项目配置：环境权限、被测服务、登记的资料文件夹、向量模型、各步骤用的模型、钩子 | 框架命令改，也可以手改 |
| `raw/` | 复制进来的少量原始资料（`qa.py ingest`），只读 | 框架 |
| `wiki/index.md` | 知识库目录 | AI 整理，人审 |
| `wiki/模块清单.md` | 全项目统一的模块名、上级模块、别名 | AI 整理，人审 |
| `wiki/modules/<模块>.md` | 每个模块现在的规则、口径、依赖、配置在哪张表 | AI 整理，人审 |
| `wiki/耦合关系.md` | 哪个数值被哪些模块改、哪些模块读、约束（脚本用它查漏测） | AI 整理，人审 |
| `wiki/risks/风险清单.md` | 测试经验清单：每类风险是什么、怎么测、怎么判对错 | AI 整理，人审；漏测回流会补进来 |
| `wiki/过时资料.md` | 资料里已经不用的规则，精确到那一句 | AI 登记，人审 |
| `wiki/log.md` | 知识库改动记录 | AI |
| `reqs/R001-标题/需求.md` | 需求原文（导入的，AI 不改写） | 框架导入 |
| `reqs/R001-标题/测试点.md` → `审核.md` → `最终测试点.md` | AI 出的测试点 → 人逐条审 → 定稿 | AI / 人 / 框架 |
| `reqs/R001-标题/变更_时间/` | 需求改了：新旧对比、测试点变更、变更审核、这次变更的回归清单 | 框架 / AI / 人 |
| `reqs/R001-标题/执行记录_轮次.md` | 手工执行结果 | 人 |
| `defects/D001-标题.md` | 缺陷记录（严重程度、是否漏测、归类、现象、原因、以后怎么测） | 人（AI 可帮填） |
| `autotest/api/` | 接口文档（`ingest --api`、抓包 `--har`） | 框架导入，人补充 |
| `autotest/tests/` | pytest 用例（多个被测服务时各有子目录） | AI 写，人看断言 |
| `autotest/invariants.py` | 不变量：每个用例结束后自动检查（金币不为负、资产守恒……） | AI 写 |
| `autotest/conftest.py` | 服务地址夹具、自动查不变量 | 框架 |
| `autotest/runs/时间/` | 每次运行的结果、摘要、归因 | 框架 / AI |
| `regress/版本/` | 版本回归清单和回归报告 | 框架 / 人 |
| `metrics/指标.md` | 采纳率、编造、补充、漏测率、模型用量 | 框架 |
| `templates/`、`prompts/` | 项目自己的模板和任务说明（同名文件覆盖框架自带的） | 人 |
| `.qa/` | 框架的进度和记录：state.json（进度）、sources.json（资料来源）、calls.jsonl（模型调用）、index.sqlite（资料索引，不进 git） | 框架 |
