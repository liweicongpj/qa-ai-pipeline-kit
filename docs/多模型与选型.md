# 多模型与选型

## 两种用模型的方式

| 方式 | 怎么用 | 适合 | 用量记录 |
|---|---|---|---|
| AI 工具干活 | 在工作区开 Claude Code / Codex / Gemini CLI 会话，照 `prompt` 打印的任务说明做 | 整理知识库、写用例这类要读写很多文件的活 | 工具自己的统计；可以 `usage add` 手动补记 |
| 框架直接调接口 | `gen <步骤>`（每一步都能）、`bench` | 正式部署、网页、钩子和 Jenkins 自动触发；模型对比 | 自动记 token、耗时、费用、查了几次资料 |

## 配模型清单

1. 把框架里的 `models.example.json` 复制一份，改名 `models.local.json`（不会上传 GitHub），删掉用不到的
2. 密钥放环境变量（Windows：`setx ANTHROPIC_API_KEY 你的密钥`，重开终端），配置里只写环境变量名
3. `python qa.py models` 看清单和密钥是否设好；`python qa.py models --test sonnet` 试调一次（只问一句，花费很少）

支持的接入方式：

| provider | 用于 | 说明 |
|---|---|---|
| anthropic | Claude | 官方 anthropic SDK，流式请求，自动用提示缓存；Opus 5.5 / Sonnet 5.5 默认开 `fallbacks: "default"`（被安全分类器拒绝时服务端自动换模型重跑），不要就删掉这一项 |
| openai | OpenAI、DeepSeek、通义千问、Kimi、智谱、本地 Ollama / vLLM 等所有 OpenAI 兼容接口 | 配 base_url 和 model；新一代 OpenAI 模型要配 `max_tokens_param: max_completion_tokens` |
| gemini | Google Gemini | 密钥走请求头 |
| cli | 本机命令行 AI 工具 | 不用 API 密钥，用工具自己的登录额度；claude 的 JSON 输出带 token 和费用 |
| mock | 假模型 | 不花钱，熟悉流程、自检用 |

项目也可以在工作区 `qa.config.json` 的 `models` 里加只给这个项目用的模型（比如内网部署的模型）。

## 多模型结合

在工作区 `qa.config.json` 里给每个步骤配默认模型，写成列表就是“前一个失败用下一个”：

```json
"stage_models": {
  "testpoints": ["opus", "deepseek"],
  "wiki-build": "opus", "wiki-update": "sonnet", "wiki-merge": "sonnet", "feedback": "sonnet",
  "req-change": "opus", "cfg-check": "sonnet",
  "tests-plan": "sonnet", "tests-write": "sonnet",
  "triage": "haiku", "wiki-lint": "haiku",
  "default": "sonnet"
}
```

`gen <步骤>` 不写 `--model` 就按这里选；没配的步骤用 `default`。`--model a,b` 临时指定（也可以写多个）。

直接调模型时的几个开关（`qa.config.json` 的 `gen`，都有默认值，一般不用改）：

| 配置 | 默认 | 说明 |
|---|---|---|
| `retries` | 2 | 限流、服务端 5xx、断网、超时这类临时故障，等一会儿重试几次（等待时间每次翻倍） |
| `retry_wait` | 5 | 第一次重试前等几秒 |
| `repair_rounds` | 2 | 检查不过（测试点解析不出、知识库格式检查有新问题、用例代码收集失败、写了不该写的文件）时，把问题发回去让模型改几轮 |
| `max_tool_turns` | 10 | 模型最多查几次资料（检索、找表查表、查缺陷、读文件），用完就必须给结果 |
| `tool_chars` | 12000 | 每次查资料的结果最多给模型看多少字 |
| `step_timeout` | 1800 | 一步的总时间（秒）：到点后不再查资料、不再返工、不再重试，保留结果等人看 |

模型清单里也可以按模型写 `max_input_chars`（提示词最多多少字，超过就把资料按比例压短）、`tool_chars`、`max_tool_turns`：本地小模型上下文短，要比云端模型给得少。

能边查边写的接入方式：anthropic、openai（OpenAI 兼容接口，包括 DeepSeek、通义千问等支持函数调用的）。gemini、cli 只用框架放进提示词的资料；
某个兼容接口不支持函数调用时，在模型清单里给它加 `"no_tools": true`，或运行时加 `--no-tools`。每次的提示词和输出存在工作区 `.qa/gen/`（不进 git），出问题时可以对着看。

“边查边写”是什么：框架先按步骤拼好一份资料（检索到的原文、相关的配置表和关联、知识库页），但拼的时候只能按需求字面去猜要哪些资料。
模型写的过程中发现还缺（比如看到名鱼表的 species 字段，要知道鱼种表里有什么；或者文档说法和配置对不上，要读整份文档核对），就自己调只读工具去查：

| 工具 | 查什么 |
|---|---|
| search | 资料索引：策划文档、以前的需求和最终测试点、配置表卡片、历史缺陷 |
| cfg_find / cfg_show / cfg_links | 找表、精确查行（可以连带查关联表）、看表之间的关联 |
| history_find | 历史缺陷 |
| read_doc / read_file | 整份文档、工作区里的知识库页和需求 |
| source_grep / source_read | 被测项目的代码（只有完整代码权限 access source 时才有，限在 source_paths 里） |

模型只能查、不能写；结果由框架收、检查、只写这一步该写的文件。查的次数有上限（`max_tool_turns`），最后一轮会明确告诉模型“别再查了，直接给结果”。
出测试点时，这个需求以前的测试点、定稿和审核结果不放进检索结果、工具也查不到（重新生成、`bench` 对比时模型不会照抄旧答案）。

### 本地模型

本地部署的模型（Ollama、vLLM、LM Studio、Xinference，或公司内网的模型服务）只要提供 OpenAI 兼容接口，用法和 DeepSeek 完全一样：
provider 写 openai，base_url 写本地地址（Ollama 是 `http://localhost:11434/v1`），密钥不需要就不写 `api_key_env`，价格写 0。

区别在“边查边写”：要模型本身支持函数调用（Qwen3、Llama 3.1 以上、DeepSeek 开源版等大多支持；7B～8B 的小模型常调错工具或格式不对）。
不支持或调不好的，给它加 `"no_tools": true`：框架照样把资料拼进提示词，只是模型不能自己再查。检查不过发回去修改、出错重试、换模型这些流程和云端模型一样。
本地模型能不能用于某一步，用 `bench` 和云端模型同题对比、看采纳率再定。

### 实测：DeepSeek 真跑（2026-11-28，钓鱼塘正式工作区的副本）

| 步骤 | 模型 | 调用 | 查资料 | 返工 | 费用（按高峰价估） |
|---|---|---|---|---|---|
| 整理知识库（先建模块清单） | deepseek-flash | 输入 6.7 万 + 输出 1.6 万 token，78 秒 | 10 次 | 1 轮（来源写了不存在的路径） | 约 0.06 美元 |
| 整理知识库：名鱼模块（没有自动关联、不能读代码） | deepseek-flash | 3 次调用共 4 分 47 秒 | 51 次 | 2 轮 | 约 0.17 美元 |
| 整理知识库：名鱼模块（带自动关联、能读代码） | deepseek-flash | 3 次调用共 5 分 13 秒 | 33 次（读了 7 个代码文件） | 2 轮 | 约 0.15 美元 |
| 出测试点：R001 营业款领取与翻倍（看不到这个需求的旧答案） | deepseek-flash | 1 次调用 123 秒 | 26 次（读了云函数和逻辑代码） | 0 轮 | 约 0.06 美元 |

五次真跑（含一次作废的）实际扣费合计 1.37 元人民币（周末空闲时段价）。

出测试点的质量：出了 47 条，和人审定稿的 20 条比，完整覆盖 17 条、部分覆盖 2 条、漏 1 条（口碑档位影响钓客吃鱼速度）；
多出来的 27 条要人审才知道采纳多少。读代码带来的发现：需求里“10 分钟内出现翻倍按钮”和“没有时间窗”自相矛盾；
云端领取不校验“满 1 金”且领 0 金也会重置营业计时；免费次数绕过 15 秒广告间隔；丢回包重试会重新结算一小段营业款——都列进了“需要和策划确认的问题”。

返工是框架检查出来、发回去让模型自己改好的，不用人插手。真跑发现并修掉的框架问题：查资料次数用完时模型把工具调用当文字写进了结果（现在最后一轮会明确提醒）；登记过时原文时被原文里的加粗、表格竖线卡住（现在比对时忽略这些记号，表格格子里的 `\|` 也不再当分隔）；完整代码权限却没有读代码的工具（补了 source_grep / source_read）。

名鱼模块的表间关联，对照人工核对的 6 条真关联：没有自动关联时写对 3 条、半对 1 条（鱼种对到了行情价表，漏了鱼种主表）；
带上自动关联和代码后写对 5 条、半对 1 条，每条都标了依据（自动认出 / 代码哪个文件 / 文档），还从代码补出了存档、埋点、名鱼图文件名这些框架认不出的跨系统引用。

## 选型：bench

```
python qa.py bench testpoints R001 --models opus,sonnet,deepseek,ollama --repeat 1
```

1. 同一份提示词（需求 + 知识库 + 耦合关系）交给每个模型，各出一份测试点
2. 顺序打乱成“方案A / B / C”，每份配一张审核表；在审核完之前不显示哪个方案是哪个模型（AI 也不要透露）
3. 人逐份审核（和平时审核一样），全部填完后：`python qa.py bench report R001`，揭晓并生成对比报告：

   | 方案 | 模型 | 生成 | 采纳率 | 编造 | 人工补充 | 审核分钟 | 输入 token | 输出 token | 耗时 | 费用 | 每条采纳的费用 |

4. 选中一份作为正式测试点：`python qa.py bench adopt R001 方案B`（审核表一起带过去，直接 `accept`）

怎么看：

- **采纳率**高、**编造**少：靠谱
- **人工补充**多：漏得多
- **每条采纳的费用**、耗时：性价比
- `--repeat 2` 或 3：同一模型跑几次，看稳不稳定
- 一次对比只是一个样本，选型建议在 3 个以上不同模块的需求上重复，再看 `usage` 和 `metrics` 的汇总

## 用量

`python qa.py usage` 按模型、按步骤汇总所有调用的次数、成功数、token、缓存命中、耗时、费用；`metrics` 里也有这一节。费用：接口返回了费用就用返回的（claude 命令行会返回），否则按清单里的单价估算（Claude 的缓存写入按 1.25 倍、读取按 0.1 倍输入价）。
