# 日常用法

上手完成后，每次开工还是先 `{{qa}} status`，它会列出所有待办。常见场景：

## 来了新需求

1. `{{qa}} req new "标题" --from 需求文件 --module 模块1,模块2`
   - 需求文件可以是 Markdown、文本、Word、Excel、网页、PDF，禅道 / 飞书等系统导出的需求单也行；不给文件就按模板填
   - 模块要标全：新规则读到了哪个模块的数值，那个模块也要标上（例如“鱼竿购买要口碑达标”，口碑属于“自家塘经营”，就标 `装备,自家塘经营`），框架才会把耦合表里相关的行拉出来提醒
2. 生成测试点：`{{qa}} prompt testpoints R00X`（工作区里的 AI 做）或 `{{qa}} gen testpoints R00X --model <模型>`
3. `{{qa}} review R00X` → 人审 → `{{qa}} accept R00X`
4. 把需求定下的新规则、新耦合并进知识库：`{{qa}} prompt wiki-merge R00X` → 人审改动 → `wiki commit --merged R00X`（没有新规则就 `{{qa}} req merged R00X`）。不做这一步，以后的需求读知识库时还是旧规则
5. 接口能测的：`{{qa}} prompt tests-plan R00X` → 人审清单 → `{{qa}} prompt tests-write` → `{{qa}} autotest run`

## 项目资料改了

- raw/ 里的资料：`{{qa}} ingest --refresh` → `status` 会提示“知识库要更新” → `{{qa}} prompt wiki-update` → 人审改动 → `{{qa}} wiki commit -m "说明"`
- 登记的资料文件夹（策划案、配置表、缺陷导出）：新文档直接放进去 → `status` 提示“资料索引要更新” → `{{qa}} index`；文档类资料有变化时 `status` 还会提示知识库可能要更新 → 同上走 `prompt wiki-update`
- 缺陷系统定期导出：覆盖登记文件夹里的同名文件 → `{{qa}} index`（只处理变化的文件）

## 发现了缺陷（测试中或线上）

1. `{{qa}} defect new "标题" --req R00X --stage 测试|线上`，填严重程度、是否被最终测试点覆盖、归类、现象、原因
2. 没被覆盖的就是漏测，`status` 会提示待回流 → `{{qa}} prompt feedback` → AI 把规律写回风险清单 / 耦合关系表 → 人审 → 按提示 `wiki commit --feedback D00X`
3. 以后同类需求生成测试点时，就会用上这次的教训
4. 建了资料索引的，下次 `{{qa}} index` 时这条缺陷也会进索引（资料名“本工作区缺陷”），`history find` 能查到，不用等缺陷系统下次导出

## 版本回归

`{{qa}} autotest run --start`（多个服务就每个 `--target` 跑一遍）。摘要会和上次比：新失败、修好了哪些。失败的先归因再登记缺陷。

可以把它挂到 CI 或定时任务上；`qa.config.json` 的 `hooks.after_autotest` 可以配一条命令（比如发通知），跑完自动执行。

## 选模型、比成本

- `{{qa}} bench testpoints R00X --models a,b,c`：同一份输入给几个模型，盲审后 `bench report` 揭晓，对比采纳率、编造、补充、token、耗时、费用
- `{{qa}} usage`：所有模型调用的 token、耗时、费用，按模型、按步骤汇总
- 详见 [多模型与选型](多模型与选型.md)

## 上传到项目仓库

工作区默认只在本地。要让资料、知识库、测试点、用例和运行结果自动上传：

1. 为这个项目建一个**私有**仓库（GitHub 私有仓库、公司 GitLab 都行），不要用框架仓库
2. `{{qa}} remote set <仓库地址>`：设好以后，`accept`、`wiki commit`、`autotest run`、`metrics` 提交后会自动推送
3. 第一次推送要登录：在你自己的终端里运行 `{{qa}} sync`，按弹窗登录。之后自动推送就不用再登录了
4. 推到 GitHub 前，建议在工作区里把提交邮箱设成 GitHub 的隐藏邮箱：`git config user.email <Settings → Emails 里的 noreply 地址>`

自动推送失败（比如没登录、断网）不会影响本地提交，框架会提示你手动 `{{qa}} sync`。

## 回答待确认

`{{qa}} wiki todo` 列出知识库里所有待确认的问题（不算标题、目录、变更记录，重复的只算一次）。能回答的告诉 AI，让它改进知识页、删掉那一条，再 `wiki commit`。

## 看效果

`{{qa}} metrics` → metrics/指标.md：每个需求和每个模块的采纳率、编造、补充、漏测率，缺陷回流情况，自动化运行情况，模型用量。
