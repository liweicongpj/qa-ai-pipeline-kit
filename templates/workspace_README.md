# {{project}} · 测试工作区

这是“{{project}}”的测试工作区：项目资料的知识库、需求和测试点、接口用例、缺陷记录、回归记录都在这里，进本文件夹自己的 git。框架装在 {{kit}}。

## 怎么用

在这个文件夹里打开 AI 编程工具（Claude Code、Codex、Gemini CLI、Cursor……），它会读 AGENTS.md 里的规则。直接对它说：

| 什么时候 | 对 AI 说 |
|---|---|
| 每次开工 | “运行 qa.py status，告诉我有哪些待办，从最要紧的开始带我做。” |
| 来了新需求 | “新需求，文件在 <路径>，帮我建需求并出测试点。” |
| 需求单只在网页上 | “新需求，内容是：<粘贴需求单文字>，帮我存成需求文件、建需求、出测试点。” |
| 审核测试点 | “一条条念测试点，我说结论你记进审核表。” |
| 需求改了 | “R002 的需求文档改了，帮我更新需求、出测试点变更和回归影响。” |
| 配置表出来了 | “配置表更新了，帮我校对相关需求的测试点和用例。” |
| 接口文档到了 | “接口文档在 <路径>，导入后帮我出用例清单。” |
| 跑回归 | “帮我拼 v1.3 的版本回归清单，模块是 <模块>，只要高、中风险的。” |
| 有新资料 | “资料文件夹里加了新文档，更新索引，看看知识库要不要跟着改。” |
| 老功能还没整理进知识库 | “把 <模块> 整理进知识库。” |

没有 AI 工具时：`python "{{kit}}/qa.py" status` 看待办，`python "{{kit}}/qa.py" next` 看下一步怎么做。

## 目录

| 目录 / 文件 | 放什么 |
|---|---|
| `AGENTS.md`（CLAUDE.md、GEMINI.md 相同） | AI 在这里干活要守的规则 |
| `qa.config.json` | 项目配置：环境、被测服务、登记的资料文件夹、模型 |
| `raw/` | 复制进来的少量原始资料（大批资料留在原处，登记后建索引） |
| `wiki/` | 知识库：`模块清单.md`、`modules/`（每个模块的规则）、`耦合关系.md`、`risks/风险清单.md`、`过时资料.md`、`index.md`、`log.md` |
| `reqs/` | 每个需求一个文件夹：需求原文 → 测试点 → 审核 → 最终测试点；需求改了的记录；手工执行记录 |
| `defects/` | 缺陷记录 |
| `autotest/` | 接口文档（api/）、用例（tests/）、不变量、每次运行结果（runs/） |
| `regress/` | 版本回归清单和报告 |
| `metrics/` | 指标：采纳率、漏测率、模型用量 |
| `.qa/` | 框架的进度和记录（资料索引 index.sqlite 不进 git） |

每个文件的详细说明见框架的 docs/目录说明.md；日常流程见框架的 docs/日常.md。
