# AI 测试管线

把“测试知识 → AI 出测试点 → 人审 → 接口自动化 → 缺陷回流”做成一条有记录、可度量、能换模型的流水线。
AI 负责干活，脚本负责判断对错和记账，人负责拍板。

## 30 秒开始

1. 把这个仓库下载到本机
2. 在这个文件夹里打开任意一个 AI 编程工具（Claude Code、Codex、Gemini CLI、Cursor……）
3. 对它说：**“读 AGENTS.md，带我一步步把这套框架搭起来。”**

它会检查环境、带你先用示例项目把整条流程跑一遍，再接上你自己的项目。需要你动手的地方，它会一步步告诉你怎么做。

没有 AI 工具也能用：`python qa.py status` 告诉你现在该做什么，`python qa.py next` 告诉你怎么做。

搭好以后，日常在**工作区文件夹**里打开 AI 工具，直接说要做的事，例如：

- “运行 qa.py status，告诉我有哪些待办，从最要紧的开始带我做。”
- “新需求，文件在 D:\需求\鱼竿口碑门槛.docx，帮我建需求并出测试点。”
- “R002 的需求文档改了，帮我更新需求、出测试点变更和回归影响。”
- “帮我拼 v1.3 的版本回归清单，模块是装备和自家塘经营，只要高、中风险的。”

每个工作区里的 README.md 有完整的一张“什么时候对 AI 说什么”。

## 能做什么

- **大批资料检索**：几百份策划案（Word / Excel / 在线文档导出）、几千张配置表（Excel / CSV / JSON）、成千上万条缺陷（禅道、TAPD、Jira、飞书等导出）留在原处建索引；关键词 + 本地向量检索策划段落，配置表精确查值，缺陷按模块检索和统计；本工作区做过的需求和登记的缺陷也自动进索引
- **知识库跟着走**：需求定稿后提醒把新规则、新耦合并进知识库；资料文件夹里的文档变了，提醒更新知识库；过时的规则精确登记到“哪一句”，检索时标出来
- **早介入**：需求文档一出来就出测试点；需求改了自动对比、出“要改的测试点 + 要回归的原有功能”；配置晚到、接口没出都不用干等
- **统一模块名**：模块清单记标准名、上级模块和别名，各人写法自动统一；按需求内容推荐涉及的模块；老项目按模块分批接入
- **版本回归**：按模块和风险等级从所有定稿测试点（加旧 Excel 用例）拼回归清单，自动化部分自动填结果，出回归报告
- **知识库**：把策划案、配置、接口文档、缺陷记录导进来，AI 整理成带出处的知识页、模块之间的耦合关系表、风险清单；资料改了一键刷新，自动提示哪些要更新
- **测试点**：来一个需求，AI 按知识库出测试点，人逐条审核后定稿；自动统计采纳率、编造数、补充数
- **模块耦合**：查出“只测了购买、没考虑打折券”这类跨模块问题：生成时带上相关模块，漏了会提醒，两两组合算法生成组合用例，不变量在每个用例结束后兜底
- **接口自动化**：AI 按接口文档写 pytest 用例，一条命令启动服务、跑用例、和上次对比；失败由 AI 归因、人确认
- **缺陷回流**：漏测的缺陷写回知识库，下一个需求就用得上
- **多模型**：Claude、OpenAI 兼容接口（DeepSeek、通义、Kimi、智谱、本地 Ollama 等）、Gemini、命令行 AI 工具都能接；每次调用记 token、耗时、费用；不同步骤可配不同模型；同一需求多个模型盲审对比，用来选型
- **三种环境**：无代码权限（手工执行记录、抓包导入成接口文档）、开放接口或协议（接口自动化，HTTP / TCP / WebSocket）、完整代码权限（对照代码核对规则、按代码改动推荐回归范围）
- **多系统、多项目**：Windows / macOS / Linux；被测服务可以是本机、公司测试服或云上的任意地址，一个项目可接多个服务和多套环境；需求、缺陷、指标按功能模块归类

## 目录

```
qa.py            命令行入口（只用 Python 标准库）
qakit/           各功能的代码：工作区、知识库、需求、检索、自动化、回归……（见 docs/开发说明.md）
qa_index.py      资料索引：读 Word / Excel / 网页 / PDF / JSON，检索、查配置表、查缺陷
qa_models.py     模型接入
prompts/         每一步交给 AI 的任务说明（项目可以覆盖）
templates/       工作区模板
docs/            上手步骤、日常用法、架构、检索、多模型、扩展、目录说明
examples/        示例项目：资料、接口文档、需求、能本地跑的被测服务、样例用例和不变量
tests/           解析函数的细粒度测试（python -m pytest tests）
models.example.json   模型清单样例（复制成 models.local.json 再改）
```

项目的资料和产出放在单独的“工作区”文件夹（`python qa.py init` 生成），不放在这个仓库里。框架和工作区里每个文件、每个目录放什么，见 [docs/目录说明.md](docs/目录说明.md)。

## 要求

Python 3.10 以上、git。依赖：`python qa.py setup`（pytest、httpx；示例服务用 fastapi、uvicorn；调 Claude 接口用 anthropic）。

## 自检

`python qa.py selftest`：在临时文件夹里用示例项目把整条流程走一遍（用假模型，不花钱），不碰你的任何文件。改了框架代码，再跑一下细粒度测试：`python -m pytest tests`。
